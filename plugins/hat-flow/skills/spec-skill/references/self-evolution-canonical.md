## 自进化过程准则（受管 · 全局注入）

> 本区块由 `spec-skill` 统一维护、各自进化技能启动时直接注入其绝对路径，**自进化流程不得改它**。完整规范见 spec-skill 的 `## Self-Evolution Capability`。

**dogfooding 收什么**——每轮收尾要复盘的「摩擦点」有两类，**都在自进化范围内**，别只盯第一类：
1. **技能与实际不符**：流程缺步 / 顺序错 / 停点不对 / reference 不贴合 / 标准模糊。
2. **执行返工**：技能与脚本本身没错，但我**凭记忆猜了字段名 / 参数 / 文件名 / 数据形状**、先写命令再报错回改，绕了弯路。← 过去常被漏掉，于是同一类低级错误反复犯。这类也必须沉淀。

**先验后做（pre-flight · 根治第 2 类）**：对**任何形状不确定**的东西（API / JSON 字段、CLI 参数、文件名、目录结构、产物 schema）动手前，**先花一步确认真实形状**——`--help` / `ls` / 读一条样本 / 查文档——**再操作**，不凭印象直接写命令等报错。一次确认的成本 ≪ 一次错跑 + 回改 + 多花的 token。**尤其**：脚本静默产出空结果（空白图 / 空表 / 0 行）而不报错时，第一反应是回去核对字段 / 路径对不对，而不是接着往下跑。

**裁决漏斗**——每个摩擦点按序找**最高**出口，命中哪层停哪层，经验库是最底层兜底：
1. 流程问题（缺步 / 顺序错 / 停点不对 / 该调没调）→ 改 **SKILL.md 正文**
2. 某 reference 不贴合 / 可优化；**或某次返工暴露了一份可文档化的形状**（字段名 / 参数 / 路径速查）→ 改 / 补**对应 reference**（如「数据形状速查」），让它下次随注入进上下文、不再靠猜
3. 通用判断规则（适用多数场景）→ 写进项目 **CLAUDE.md**
4. 稀有 / 例外经验（前三层都小题大做）→ 落 **`references/lessons.md`**（经验库）

> **第 2 类返工的归途**：① **能文档化的形状**（如 `meta.json` 落盘字段、session JSON 用 `lines` 非 `rows`）走漏斗②沉进对应 reference，下次注入即免猜；② **纯纪律性疏忽**（信息本可 `--help`/`ls` 当场拿到、只是没做）由上面「先验后做」覆盖，**不为一次性疏忽建经验库条目**；但**若反复在同一处栽**，说明该技能缺一个针对性的 pre-flight 检查点 → 按漏斗①补进 SKILL 正文（如某 Phase 开头「先 `--help` 再跑 X」）。

**写入闸（每次往经验库写之前）**：先回答「为何不能上移到 ①正文 / ②reference / ③CLAUDE.md」。答得上来 → 上移，不进经验库。经验库是兜底、不是默认垃圾桶。
> 编排族（orchestrator + workers）补一问：「下次哪个技能的哪个决策点会读到它？」——执行细节归 worker、编排决策归 orchestrator；答不出唯一归属就别写（要么固化进正文、要么还没定位到复用点），**绝不把同一软经验镜像进多个技能**。

**整合（触发式，非每轮强做）= 升级 + 淘汰 + 归纳覆写**：反复命中的**升级**固化进流程后移除；超限 / 过时的**淘汰**进 `lessons-archive.md`（不删、可回溯、永不注入、高重要度豁免）；**归纳覆写**合并重叠、刷新「上次命中」。经验库表格化（`经验|重要度|来源|上次命中`）、头部记 `上次整合: YYYY-MM-DD`、**硬上限 ≤15 条**。触发判据只看两样：达硬上限 / 距上次整合 ≥1 天（或到上线·里程碑节点）→ 做；本轮无新经验 / 刚整合过 → 跳过。整合后刷新头部日期。

**changelog 纪律**：`references/changelog.md` **仅在本轮真正改了 skill 定义**（SKILL.md / reference / 经验库结构）时写一条，记「改了什么 + 为何」，最新在最上。**没改 skill 就不写**——它是修订/回溯日志，**不是每轮运行或 dogfood 的流水账**。dogfood 的详尽经过蒸馏进正文/经验库或丢弃，不单独灌进 changelog。
